# Reporter support escalation and center settings

Admin → Settings → Support center controls enabled state, owner wait (default 2 minutes), unanswered support wait (default 5 minutes), up to 8 labeled phone numbers, display hours/time zone and call instructions. Phone list starts empty; no fictitious contact number is published. Hours are informational, not an automatic opening/closing schedule.

An expiring status capability gates all public report data. Escalation creates one PUBLIC_REPORT ticket per report under a report row lock and partial unique index. No fabricated customer account or owner impersonation is used: requester_id is nullable only for a report-linked PUBLIC_REPORT ticket. Existing authenticated support tickets retain requester access.

Staff inbox uses existing live-session, permission and assignment checks. Anonymous tickets use left joins, and staff see the linked report, code serial, vehicle and owner name/ID. The public response is a separate allowlist: no owner identity, code secret, staff identity or internal notes. The reporter sees the latest 100 public staff replies. Empty Realtime invalidations trigger an authoritative refetch, with visible-tab polling every 15 seconds while connected and every 5 seconds otherwise. Connectivity does not guarantee delivery; reconnect and eligibility-boundary refreshes provide recovery. See reporter-reliability.md. Reporter free-text messaging is not implemented in this change.

Calls are offered only after escalation, the configured wait, an unanswered/open ticket, an open report and configured numbers. Disabling escalation also disables new call offers; existing ticket replies remain readable until report expiry. The contact page rechecks eligibility; it does not blindly reveal numbers from a query string. Settings updates apply to existing reports as well as new reports. Public contact numbers are intentionally shareable once displayed, not secrets.

Database settings are private and available only through a live SUPER_ADMIN RPC; edits are audited. Public wrapper is security invoker, private report function security definer with a capability check. Anonymous schema USAGE permits name resolution, not table access; private schema must remain unexposed. RLS-no-policy INFO for private settings is intentional deny-direct-access. Existing advisor WARN findings are unchanged, including [leaked password protection disabled](https://supabase.com/docs/guides/auth/password-security#password-strength-and-leaked-password-protection).

Verification: 100 Node tests, TypeScript, ESLint and webpack production build pass. tests/report-support-center.sql exercises live database code as anon/authenticated in an always-rolled-back subtransaction: admin denial, invalid/expired token, premature escalation/call denial, idempotence, staff context/list visibility, public reply visibility and internal-note isolation. Fixtures and settings restore automatically; no real customer ticket is changed.
